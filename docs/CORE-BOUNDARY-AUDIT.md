# Core 与事件包边界审计

2026-11-17 更新：用户明确要求 Core 不包含事件专属功能。**当前 Core 仍未达到这一目标**：字段专属适配、烘焙调度及旧接口兼容仍在 Core。上次把它称为清理干净是不准确的。交付物拆分只是分发层面的改进，不等同于实现层面完成解耦。

事件包拥有自己的效果、设置、资源、面板参数与旧数据的迁移声明；Core 提供通用执行、存储、编辑器接入及可复用的原语。新增事件不应要求修改 Core 的专用设置、识别逻辑或默认效果。

## 已清理的耦合

- 全局设置、名称、默认值和文案由事件包声明；Core 按事件 ID 隔离和持久化设置，并通用生成 UMM 面板。状态事件的状态选择和预警计时也在包内脚本中。
- 原生装饰的默认颜色、标签和旧数据迁移映射由包声明。载体标记 `pev/field` 是已写入谱面的通用存储契约，继续保留；无包声明时，通用非空标签用于规避游戏原生装饰重置问题。
- 字段编辑器预览的键和参数映射由包声明；生产代码不通过噪域事件 ID 或特定参数名识别字段。`Choice` 下拉选项由包定义，字段基础形状类型仍属于原语。
- 旧字段渲染使用的 PNG、视觉配置和辉光权重移到事件包中；Core 不再内嵌事件 PNG。CPU 贴图缓存按资源提供者及其配置隔离，字段参数未提供时采用中性默认值。
- GPU 路径从各包声明加载资源、波形、视觉数值和采样设置；按提供者隔离运行及故障回退，避免某一包的加载失败禁用其他包。单一真实 bundle 已在游戏内验证；多个不同有效 bundle 的并行运行尚未验证。
- Phira 色彩归属算法已迁入事件包的 `workers/palette.js`；Core 提供通用、有界的后台栅格、向量表达式与最近种子传播能力，脚本不获得 CLR、文件、网络或 Unity 对象。旧 C# 参考算法只编译进诊断版，用于逐字节回归。400×224、六区域在游戏 Mono 中通用路径约 17–19 ms，原实现约 27 ms；不同设备与复杂谱面仍需实测。
- CPU 回退的覆盖、边缘、辉光、颜色、颗粒和撕裂算法现由事件包 `workers/legacy-bake.js` 驱动，分辨率与帧数策略由 `workers/legacy-plan.js` 决定；核心提供受限的像素运算、输出预算和后台任务。旧 `NoiseComposer`、配置解析与烘焙公式只编译进诊断版。游戏中 80 组覆盖/边缘/辉光、16 个完整帧及 4 帧实际撕裂与旧实现逐字节一致，250 组烘焙计划与旧策略一致，真实 GPU 故障也已回退到包内 CPU 程序。96 帧 192×132 在当前机器后台约 4 秒，观察到最慢游戏帧约 10 ms；2 帧 1024×1024 约 3 秒。字段专属参数适配、缓存及调度仍在 Core，需要继续泛化。
- 渲染和烘焙必须携带明确的包来源，不再扫描已安装事件以猜测噪域提供者；缓存以加载实例隔离，重新加载同一路径时也不会复用旧实例的数据。旧纹理解码和旧 profile 类型仅保留在诊断版。
- GPU 覆盖图的资源格式、分辨率、pass 次序、绑定和辉光权重由事件包 `pipelines/coverage.json` 声明；Core 使用受限的通用计算图执行器，旧实现仅留在诊断版。真实游戏 GPU 测试对空区域、三态、组合、反转、触点、不同时间和分辨率逐像素对比通过。字段适配器及其调度仍是待迁移代码，不能据此宣称 Core 已清理完成。
- 画面合成的材质角色、条件选择、图层与着色器输入绑定由包内计算图声明。通用合成器与仅保留在诊断版的旧合成器在游戏内对 24 种采样、触点、颜色和图层组合逐像素比较一致，且每组都确认实际产生可见内容。schema 4 不再强制十种固定着色器角色；字段适配器与旧 CPU 合成仍待迁移。
- 星球与噪域几何组合的命中规则和触点动画由事件包 `workers/contacts.js` 实现，Core 提供有界、只交换 JSON 的脚本控制器以及星球位置采集。游戏内用旧逻辑对照 200 帧随机进出、反转和时间回跳，通过后旧逻辑只保留在诊断版；四区域、最多十二个输入点的测试均值约 0.30 ms/组，空输入且无残余动画时跳过执行。大量同屏排序层级的开销仍需针对目标机器实测。
- 状态事件通过包隔离的通用标签值传递状态，覆盖顺序、清理与跨包隔离已经实测；旧的内部 `fieldState` 调用暂保留兼容适配。字段模式名称、默认值、着色标志、图层、颜色与触点的对应关系现由包内计算图声明；核心字段适配器仍需进一步泛化，不能视为彻底解耦。
- `Diagnostics/` 的事件专属测试夹具只编译到单独的诊断版 DLL，不进入正式 Core DLL。构建诊断版使用 `dotnet build src/PEV.Core/PEV.Core.csproj -c Release -p:IncludeDiagnostics=true`，输出在 `bin/Release-diagnostics/`；正式构建仍输出 `bin/Release/`。

## 升级与兼容

升级 Core 时必须同时升级噪域事件包到仓库中的 `pev.noise-field` **1.10.0 或更新版本**。较旧事件包缺少包内 CPU 程序或计划，不能使用本版 CPU 回退；它们也可能缺少 GPU 所需配置。旧谱面的事件 ID、参数和载体格式不变，可通过升级后的事件包读取；旧评论载体的迁移由包内声明驱动。其他没有使用该内部原语的 schema 1/2 事件不因本次资源迁移而需要升级。

## 保留的能力与限制

目前 `fx.field` 在 Core 中混合了通用资源生命周期、排序等基础设施与 Phira 噪域专属计算和规则。后者应迁入事件包，前者应通过不依赖特定事件的能力接口提供；迁移时需保留沙箱边界、原生 depth、旧谱面、三态、触点和游戏实测，不应把任意原生代码加载偷偷引入 Core。

已确认的待迁移实现包括 `NoiseTextureFactory` 中的字段专属参数与烘焙调度，以及 `NoiseFieldGpuMasks` / `NoiseFieldGpuCoordinator` 和 `NoiseFieldRenderer` 中的事件专属适配。删除这些代码前，事件包必须能表达并驱动对应流程，不能以牺牲画面或关闭 CPU 回退冒充解耦。

分发脚本现生成不含事件文件的 Core 压缩包和一个独立噪域 `.event`。事件包通过通用 schema 4 包含状态控制事件；仅安装该包时，两个事件入口、状态脚本和 GPU 渲染已在游戏实测。空事件目录下 Core 也能独立启动。分发形式已经拆开，但 Core 内的事件专属逻辑尚未迁出，因此这仍是中间产物。

Unity shader bundle 已构建并内置于噪域事件包。游戏内已检查资源加载、GPU 接管、单层与两层 depth、实时场景采样开关、三态和反转镂空；更复杂谱面、多个不同有效 GPU 资源提供者的并行显示及完整游戏画面与参考的逐帧对照仍未完成，详见 [发布验证记录](NOISEFIELD-RELEASE-VALIDATION.md)。

事件全局设置属于 schema 3 / 脚本 API 2；内部字段接线可以调整，公开契约的变更须更新版本和 SDK。设置保存在本机，不写入谱面；卸载事件包后保留其设置。
