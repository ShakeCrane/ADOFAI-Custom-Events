# Core 与事件包边界审计

2026-11-17 更新：用户明确要求 Core 不包含事件专属功能。**当前 Core 仍未达到这一目标**：虽然资源和配置已搬进事件包，CPU 噪域合成、Phira 色彩归属算法及为该效果定制的 GPU pass、状态和触点调度仍在 Core。上次把它称为清理干净是不准确的。交付物拆分只是分发层面的改进，不等同于实现层面完成解耦。

事件包拥有自己的效果、设置、资源、面板参数与旧数据的迁移声明；Core 提供通用执行、存储、编辑器接入及可复用的原语。新增事件不应要求修改 Core 的专用设置、识别逻辑或默认效果。

## 已清理的耦合

- 全局设置、名称、默认值和文案由事件包声明；Core 按事件 ID 隔离和持久化设置，并通用生成 UMM 面板。状态事件的状态选择和预警计时也在包内脚本中。
- 原生装饰的默认颜色、标签和旧数据迁移映射由包声明。载体标记 `pev/field` 是已写入谱面的通用存储契约，继续保留；无包声明时，通用非空标签用于规避游戏原生装饰重置问题。
- 字段编辑器预览的键和参数映射由包声明；生产代码不通过噪域事件 ID 或特定参数名识别字段。`Choice` 下拉选项由包定义，字段基础形状类型仍属于原语。
- 旧字段渲染使用的 PNG、视觉配置和辉光权重移到事件包中；Core 不再内嵌事件 PNG。CPU 贴图缓存按资源提供者及其配置隔离，字段参数未提供时采用中性默认值。
- GPU 路径从各包声明加载资源、波形、视觉数值和采样设置；按提供者隔离运行及故障回退，避免某一包的加载失败禁用其他包。单一真实 bundle 已在游戏内验证；多个不同有效 bundle 的并行运行尚未验证。
- `Diagnostics/` 中出现具体事件 ID 和参数用于测试夹具，不参与一般事件的功能调度。

## 升级与兼容

升级 Core 时必须同时升级噪域事件包到仓库中的 `pev.noise-field` **1.0.1 或更新版本**。旧版 1.0.0 事件包没有声明原先内嵌于 Core 的纹理和配置，单独搭配新 Core 不能渲染；日志会提示升级事件包。正式发布应把新 Core 和新事件包一起分发。旧谱面的事件 ID、参数和载体格式不变，可通过升级后的事件包读取；旧评论载体的迁移由包内声明驱动。其他没有使用该内部原语的 schema 1/2 事件不因本次资源迁移而需要升级。

## 保留的能力与限制

目前 `fx.field` 在 Core 中混合了通用资源生命周期、排序等基础设施与 Phira 噪域专属计算和规则。后者应迁入事件包，前者应通过不依赖特定事件的能力接口提供；迁移时需保留沙箱边界、原生 depth、旧谱面、三态、触点和游戏实测，不应把任意原生代码加载偷偷引入 Core。

已确认的待迁移实现包括 `NoiseComposer` / `NoiseTextureFactory` 的旧 CPU 特效，`NoiseFieldColorOwnership` 的 Phira 色彩归属，以及 `NoiseFieldGpuMasks` / `NoiseFieldGpuCoordinator` 中写死的 pass 顺序、辉光和状态行为。删除这些代码前，事件包必须能表达并驱动对应流程，不能以牺牲画面或关闭 CPU 回退冒充解耦。

分发脚本现生成不含事件的 Core 压缩包及独立事件文件。空事件目录启动和独立事件安装均已在游戏实测；目前状态控制仍是第二个独立 `.event`，尚未达到“核心 + 一个完整噪域包”的最终交付形态。两项待办都完成之前，分包结果只能视为中间产物。

Unity shader bundle 已构建并内置于噪域事件包。游戏内已检查资源加载、GPU 接管、单层与两层 depth、实时场景采样开关、三态和反转镂空；更复杂谱面、多个不同有效 GPU 资源提供者的并行显示及完整游戏画面与参考的逐帧对照仍未完成，详见 [发布验证记录](NOISEFIELD-RELEASE-VALIDATION.md)。

事件全局设置属于 schema 3 / 脚本 API 2；内部字段接线可以调整，公开契约的变更须更新版本和 SDK。设置保存在本机，不写入谱面；卸载事件包后保留其设置。
